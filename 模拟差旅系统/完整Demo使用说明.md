# 智能差旅提单 Demo

页面与数据运行在本机。助手由 Dify Chatflow 整理差旅草稿，本地模拟系统提供员工、交通、城市、创建和回执接口。Dify 通过带鉴权的独立 HTTPS 通道访问这些模拟接口。

## 打开与启动

- 助手：[http://127.0.0.1:8766/assistant](http://127.0.0.1:8766/assistant)
- 模拟控制台：[http://127.0.0.1:8766/simulator](http://127.0.0.1:8766/simulator)
- 原接口文档：[http://127.0.0.1:8766/docs](http://127.0.0.1:8766/docs)

在终端执行：

```sh
cd /Users/khalil/Documents/智能提单项目/模拟差旅系统
./run-demo.sh
```

脚本在后台启动主服务、鉴权网关与临时通道。重复执行会复用本脚本记录的存活进程；遇到其他程序占用端口会停止并说明，不结束未知进程。首次缺少依赖时安装锁定的 Python 依赖；前端产物缺失时才执行安装和构建。

```sh
# 查看本 Demo 的进程与地址
.venv/bin/python demo_control.py status

# 更新 Python 代码后，仅重启本地服务，保持通道地址
.venv/bin/python demo_control.py restart-local

# 只关闭云端访问通道
.venv/bin/python demo_control.py stop-bridge

# 停止本 Demo 管理的全部进程，保留历史会话、单据及回执
./stop-demo.sh
```

原 `./run.sh` 仍可用于只运行本地 API 与页面；不要与 `run-demo.sh` 同时占用 8766。前端源码变更后，在 `frontend` 目录执行 `npm run build`，刷新页面即可加载。

## 通道重启后的必要操作

临时 Cloudflare 通道每次重新建立都会生成新地址。**如果通道地址变了，必须更新 Dify 的 `DEMO_API_BASE_URL` 并发布更新。** 仅重启本地服务可使用 `restart-local`，不改变仍存活的通道地址。

当前测试应用：[差旅申请助手-MVP1.2-测试](https://cloud.dify.ai/app/9f14a8eb-d849-41cb-8dbd-b66829b17edb/workflow)。在「环境变量」中设置：

| 变量 | 值的来源 |
|---|---|
| `DEMO_API_BASE_URL` | 启动脚本输出的 HTTPS 地址，不带末尾 `/` |
| `DEMO_API_TOKEN` | `.local/bridge.json` 的 `token`；类型保持 Secret |

已有网关凭证保持不变。修改环境变量后点击「发布更新」，旧的已发布版本不会自动使用新地址。

如需重新导入全部工作流，用下面的命令生成仅供当前机器使用的运行文件：

```sh
../交付物/完整Demo_Dify接入/.venv/bin/python prepare_dify_runtime.py
```

在上述 Dify 应用的更多操作中导入 `.local/差旅申请助手-完整Demo-本机运行.yml`。这个文件包含网关凭证，不用于分享。公共交付文件 `交付物/完整Demo_Dify接入/差旅申请助手-完整Demo-可导入.yml` 的两个环境变量为空。

当前机器已安装官方 cloudflared 2026.9.1，位置 `.local/bin/cloudflared`。如果迁移机器，需先从 Cloudflare 官方来源安装适配操作系统的 cloudflared，并准备 Dify 配置；本项目不会复制用户机器上的凭证到其他机器。

## 演示流程

1. 打开助手，新建会话，输入“我想从杭州东站去深圳北站出差拜访客户”。已有内容会展示为草稿卡片，缺失信息由助手继续追问。
2. 根据助手回复的文字提示，直接发送补充信息或修改要求，例如“把事由改为项目验收，其他不变”，也可以点击「编辑申请」填写表单。卡片仅保留「编辑申请」和「提交单据」，不提供「继续对话」按钮。回复说明本轮变化并展示更新后的卡片；历史卡片保留为只读。
3. 点击「编辑申请」打开右侧抽屉。申请人、部门和费用承担公司只读；可编辑差旅类型、事由、所有行程，支持城市搜索、交换城市、增加、插入和删除行程。移动端使用接近全屏的抽屉。
4. 在抽屉内填全后点击「提交单据」。字段有误时留在抽屉并提示问题，已填内容保留。抽屉没有「保存草稿」按钮；直接关闭尚未提交的修改会提示确认。
5. 草稿信息完整时，也可直接点击卡片的「提交单据」。成功后卡片变为「已提交」只读，点击「在模拟系统中查看」可核对模拟单号、事由和行程。
6. 如需演示失败，在模拟控制台将提交结果切换为「失败」并填写说明，然后提交另一份完整草稿。助手显示实际错误原因，并保留本次完整内容（包括抽屉修改），提示可前往差旅系统继续编辑。Demo 仅展示这段流程说明，不提供系统跳转编辑；完成后将场景恢复为「成功」。

日期请按演示当天调整，例如“2026年10月18日出发，10月20日从深圳回杭州，两段飞机经济舱，普通差旅”。场景切换只影响新的创建请求，回放旧请求不会改变旧结果。网络中断或结果不确定时，通过页面提示查询结果；系统沿用原业务请求号，避免重复创建。只有明确失败才显示失败草稿说明。

AI 回复已隐藏「默认与映射说明」及同类默认说明段落。业务默认值、城市映射和必要追问继续生效。卡片展示规范城市名；编辑抽屉保留原始地点输入，明确重新选择城市后按新输入校验。

本地抽屉提交产生的新内容会在下一次对话前同步到 Dify。公共 DSL 的 N09/S01 输出模板已随本次改动重建，但本次没有重新导入或发布远程 Dify 工作流；当前助手通过本地展示层兼容已发布的旧模板。

## 删除历史会话

历史会话右侧的垃圾桶图标可删除对应会话。点击后弹窗显示会话标题和删除范围；选择「取消」会保留原内容，选择「确定删除」才执行删除。

- 删除当前会话后自动切换到其他会话；删除最后一个会话后回到欢迎页，不自动创建空会话。
- 删除其他会话时，当前会话和输入框内尚未发送的文字保留。
- 会话及其草稿会从本地历史列表移除，刷新后仍保持删除状态。已提交单据和业务回执保留，可在模拟差旅系统中查看。
- 正在处理的会话暂不可删除；提交结果尚未确认时，需先查询结果。删除失败会在弹窗显示原因，支持重试。

本 Demo 使用本地逻辑删除，保留底层审计记录；不删除 Dify 云端会话，不提供批量删除或回收站。

## 已约定的业务范围

- 固定普通员工，21 项交通，50 条国内城市；不区分 M5，默认有提单权限。
- 无住宿城市字段或住宿接口。
- 城市查询保留原 `filter` 表单形式，支持名称、编码与已配置站点别名。昆山明确映射苏州；桐庐保留自身编码。
- 创建 JSON 保留 `remark`、`dqydbg`、`trips`；普通差旅 `dqydbg=null`。
- 创建成功或失败来自本地场景开关，不触发真实权限、历史冲突等业务校验。助手继续检查信息完整性、有效选项、日期路线和当前确认版本。
