# 差旅单据生命周期 V2 使用说明

本版本在独立分支 `feature/travel-lifecycle` 上扩展差旅申请、变更、撤回、退回、重提、审批完成和作废流程。开发前保存的旧版基线为提交 `936c625b6627cc17916895cd62998063ea586e1e`，标签为 `demo-baseline-20260913`。

生命周期 V2 使用新的 Dify Workflow 应用「差旅助手-单据生命周期-V2」。旧 Dify 应用以及旧版 `8766` 本地服务、`8767` 网关仍按原方式运行，本版本不修改它们的配置或发布内容。

## 启动与停止

在本目录执行：

```sh
./run-lifecycle.sh
```

脚本安装缺少的锁定依赖、构建前端，并启动一个 worker 的生命周期服务、独立网关和独立临时隧道：

- 员工助手：<http://127.0.0.1:8876/assistant>
- 模拟控制台：<http://127.0.0.1:8876/simulator>
- 生命周期服务：`127.0.0.1:8876`
- 生命周期网关：`127.0.0.1:8877`
- 独立数据库：`data/lifecycle.sqlite3`

查看状态不会启动或停止进程：

```sh
.venv/bin/python lifecycle_control.py status
```

停止本版本记录且身份仍匹配的进程：

```sh
./stop-lifecycle.sh
```

控制器使用 `.local/lifecycle-processes.json` 保存 PID 和进程身份。端口被其他进程占用时会停止启动并提示核对，不会结束未知进程。停止服务不会删除生命周期数据库。

## 独立配置与 Dify 更新

生命周期运行使用以下私密文件，权限均应为 `0600`，且已由 `.gitignore` 排除：

- `.local/lifecycle-dify.json`：新应用的 `app_id`、`api_key`、`base_url`、`expected_app_name` 和 `inputs`。
- `.local/lifecycle-bridge.json`：与新应用 ID 对应的独立 `token`、`public_url` 和指向 `http://127.0.0.1:8876` 的 `upstream_url`。
- `.local/差旅助手-单据生命周期-V2-本机运行.yml`：启动成功后生成，仅供当前机器导入，包含当前网关地址和 token。

可分享的源 DSL 位于 `../交付物/单据生命周期_Dify/差旅助手-单据生命周期-V2-可导入.yml`，其中 `DEMO_API_BASE_URL` 和 `DEMO_API_TOKEN` 均为空。

临时隧道重新建立后地址可能变化。发生变化时，只更新并发布新应用「差旅助手-单据生命周期-V2」的 `DEMO_API_BASE_URL`；不要更新旧应用。网关 token 作为 Secret 填入新应用的 `DEMO_API_TOKEN`。

## 演示流程

1. 打开员工助手并进入一个会话，直接说「查一下我接下来有哪些差旅」「我今天在哪里出差」「查上个月上海的差旅申请」。查询使用自然语言，没有查询条件表单。
2. 每次查询回复下方展示相关差旅单据卡片，包含单号、状态、效力、日期、路线和事由；展开「单据详情」可看完整内容和办理历史。卡片的「查看系统单据」是演示按钮，点击不会实际跳转。卡片读取当前可见版本，不展示已被替代的旧版。编辑、继续变更和取消编辑的回复也会附上对应正式单据；未提交的修改仍以草稿及差异区为准。
3. 卡片按当前资格提供撤回、变更、原号重提或作废按钮。点击撤回后先弹出二次确认，取消不会改变单据。点击作废后弹窗说明影响，可选填作废原因，再确认作废；也可点击「用对话说明」，输入「确认作废 单号，原因：客户取消会议」。直接说「撤回这张」或「作废这张」会先返回待确认卡片，再回复「确认撤回」或「确认作废」完成办理；「取消撤回／取消作废」只取消操作确认。确认期间单据已变化则拒绝办理。
4. 变更编辑支持部门、付款公司、差旅类型、事由、日期、城市、交通方式以及行程段增删；保存后核对差异和完整新安排，再确认提交。
5. 打开模拟控制台，在生命周期区域查看业务状态并执行「开始审批」「审批通过」或「审批退回」。审批操作只出现在模拟控制台，员工助手没有审批权限入口。
6. 需要演示样例时，在模拟控制台点击补充演示数据，或调用 `POST /mock/v1/lifecycle/seed`。seed 只补充缺少的 `demoOnly` 样例，不清空、不重置现有单据和场景设置，可重复执行。

语义办理中，原因可以写「客户取消会议，不需要出差」。若同一条消息又补充「先不要作废」「暂缓办理」等指令，本轮不会执行操作，需核对后重新明确确认。

网络中断或服务以 `UNKNOWN` 回执响应时，页面都会保留原 `clientRequestId` 和「查询办理结果」入口。点击该入口会先查 `/mock/v1/lifecycle/receipts/{clientRequestId}`；尚无回执时仍沿用原请求号同步，避免重复办理。查到成功或失败回执后，页面会调用会话内的 `/assistant/api/conversations/{id}/lifecycle/recover`，先把助手侧请求和草稿同步到对应终态，再清除浏览器中的待核对记录；失败草稿解除请求锁后可以继续编辑。

## 业务口径

- 已批准单据可以发起串行变更。前一笔变更审批完成后，可继续基于新的当前有效单据发起下一笔，次数不限；同一时间只允许一笔在途变更。
- 变更单在批准前尚未生效，原批准安排继续有效。变更批准后，新单成为当前有效单据，前一版只保留在历史链中。
- 「作废本次未生效变更」只结束当前变更申请，原批准安排继续有效。
- 「作废当前有效单据」结束当前有效安排；完成后不会自动恢复任何旧版。
- S005 统一显示「已撤回／退回」，具体来源以办理历史中的「员工撤回」或「审批退回」为准。
- DTO 的 `version` 用于并发校验，不代表第几次变更。页面发现目标版本变化时会保留尚未保存的输入，但禁止直接保存或提交，需刷新核对后重新准备。
- 同一草稿被自然语言更新到新 `revision` 时，未做本地编辑的表单会自动显示最新内容；如已有未保存输入，页面会保留输入并禁止保存、提交，直到用户显式选择「使用最新草稿内容」。
- 本期范围不包含报销申请、报销审批或票据核销。
