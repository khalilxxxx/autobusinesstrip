## 已实现的交互

| 用户要求 | 本轮实现 |
|---|---|
| 查询和全局回复精简 | 普通查询只说明总数与卡片入口；详情、草稿和办理回执不再逐项复述事由、部门、单号、版本及交通段。具体问题先回答问题本身。 |
| 单张完整卡片、多张简卡 | 单张复用申请卡片视觉与内容组件；多张突出单号、日期范围、状态和合并路线。每轮最多 3 张，超过时文字说明总数和展示数，并提供查看全部结果按钮。 |
| 系统查看入口 | 每张正式单据提供“查看系统单据”，超量结果提供“查看全部查询结果”；均为用户要求的演示按钮，无实际跳转。本地查看详情仍可展开。 |
| 操作由接口决定 | 正式单据的撤回、作废、变更、重提按钮资格只采用接口 `actions`，前端不再另行推导状态资格。历史轮和请求进行中的禁用属于交互保护。 |
| 明细推理回答 | Dify 新增只读 LLM，输入为业务日期、实际筛选、总数／展示数、最多三张单据的原始 `request.trips`、状态、效力及城市编码映射，不向它传入 `locations/stay` 结论。 |
| 旧轮按钮置灰 | 发送新消息即禁用此前卡片中的办理按钮，含创建草稿确认按钮；系统查看／详情／全部结果入口保留。操作归属持久化，刷新不会解锁旧卡片。 |
| 作废弹窗与语义办理 | 弹窗只有取消、确认及选填原因，已移除“用对话说明”。明确作废指令可直接办理，目标由原话与服务端选择绑定；否定、暂缓、条件或引用表达不触发写入。 |
| 统一变更抽屉 | 卡片显示实际修改后的草稿；抽屉只展示当前草稿字段，无前后差异或“保存并查看差异”。确认提交会先保存当前未保存输入，再使用新版本提交。 |

查询回放只读重查当前可见单据，不改变当前会话的结果指代或卡片操作归属。历史草稿快照不会在原目标已替代或版本改变后泄露旧内容。原有草稿冲突校验、未保存输入保护及 UNKNOWN 同请求恢复保留。
