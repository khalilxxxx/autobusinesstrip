# AI 助手草稿交互设计（已确认）

用户已于本会话确认并要求开始实现。全部面向用户的内容使用中文。

- 初步草稿即在对话中显示结构化卡片，包含已有内容及待处理事项。
- 卡片仅提供编辑、提交单据。助手回复正文提示可直接回复补充或修改信息，或者点击编辑填写表单，不提供继续对话按钮。仅最新版本可操作，旧卡片只读。
- 编辑使用右侧抽屉，移动端接近全屏。完整显示申请身份、差旅类型、事由和所有行程；支持新增、插入、删除、城市互换，城市搜索和交通选项。
- 无保存草稿按钮，无手工保存后继续对话流程。抽屉仅提交单据，提交前校验字段，关闭未提交修改需防误丢。
- 提交明确失败后，持久化本次完整信息（含抽屉修改）为草稿，提示可到差旅系统进一步编辑。Demo 只解释后续流程，不实现系统跳转编辑。
- 网络中断或结果未知不能冒充明确失败，保留原请求号查询回执，避免重复创建。
- AI 回复去掉默认与映射说明以及同类默认与建议段落；业务默认值和城市规则继续执行。卡片承担完整单据展示，文字保留修改说明、必要追问或错误。
- 范围沿用固定普通员工、现有城市和交通、差旅类型/事由/行程；不增加活动、派工、借款、同行、真实权限和历史冲突检查。

实现约束：复用现有工作流校验及模拟 HTTP 创建接口。表单提交是明确的结构化操作，不交由模型重新理解。原草稿版本、幂等和会话隔离继续有效。表单提交产生的最新状态先持久化；后续使用 Dify 会话前通过变量更新接口同步，避免旧模型状态覆盖本地结果。
