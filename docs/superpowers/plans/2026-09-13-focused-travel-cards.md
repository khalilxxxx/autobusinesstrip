# 聚焦差旅对话与卡片实现计划

目标：落实本轮用户指定的简洁回复、最多三张查询卡片、LLM 明细推理、当前轮操作及统一变更抽屉。

执行依据：用户本轮已明确要求修改这些交互；在既有新版工作树内继续实现，原目录和旧 Dify 保持不变。前端与 Dify 构建可按明确接口并行；主任务实现后端、集成、发布与真实验收。

## 接口与交互约定

- 查询接口仍返回普通单据明细及 `actions`；助手查询最多展示 3 条，`querySummary.total` 为全部匹配数，`resultIds` 仅保存展示的三条，防止指代未展示对象。
- `/workflow/v1/lifecycle/turn` 保留 `handled/reply`，查询可附加 `answerContext` 对象：`question/businessDate/filters/total/shown/documents`。documents 为本次展示单据的原始行程、状态、效力及基本信息，剔除 `locations/stay` 等预推理字段。Dify 新增 LLM 只依据该对象回答问题，不决定办理权限、不写入业务。
- `LifecycleState.cardGroups` 新增可选 `kind: query|document|draft|receipt`、`draft` 和 `interactionTurnId`。`turnId` 控制消息中的展示位置，`interactionTurnId` 持久化操作归属，保证临时卡片刷新后仍能识别历史轮。草稿组保存展示快照，展示层不依赖 `original/differences`；历史组全部办理操作禁用，查看入口保留。接口 actions 仍是操作按钮的唯一资格来源。
- 后端简化详情、草稿和成功回执文本；事实明确的查询问题由新增 LLM 节点推理。多于三条时说明总数和当前展示数量，提供演示用“查看全部查询结果”按钮。
- 前端 `DocumentPanel` 接收最新对话轮次和 busy 信息，用户发送新消息即锁定此前所有操作；创建草稿卡片同样遵循当前轮规则。抽屉保留草稿校验、并发版本及未知结果恢复。
- 作废弹窗只保留取消与确认；直接、肯定且目标唯一的语义作废可以执行，原因选填。撤回保留二次确认。否定、条件、引用表达不授权写入。
